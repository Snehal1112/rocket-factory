Factory Workflow

One feature goes in. The factory reviews the spec, builds the feature in a separate worktree, checks it, has it reviewed and merges it to your local base branch. Five pictures show how a job moves, what can stop it, which processes are involved, how an agent is started and which turns a job takes.

Notes

Left out on purpose

  • Builder permission details. Figure 4 shows the mode and the guard. The exact allowlist, the deny rules on the job folder and the builder_permissions and builder_allow keys are in docs/reference/software-factory.md (Builder permissions). The allowlist is not a sandbox.
  • Prompt cache setting. cache_ttl is unset in the core config. factory project add writes 5m into new projects. It is a setting on agent runs, not a step in the flow.
  • Release and smoke checks. scripts/release.sh and the live smoke run in scripts/live-smoke.sh are described in docs/operations/releasing.md. The release script refuses to run while tracked files have uncommitted changes. Untracked files do not block it.
